## 3. Problem

1.2 made verification evidence portable but left environment freshness advisory. A receiver could be shown `fresh` after `rubocop`/`rspec` had been upgraded, or after a waiver/baseline had been injected, if the caller didn't supply `current_analyzer_versions`. MCP reused cached analyzer versions as current observation. Repair could hide a boundary change behind `gate: PASS`.

## 4. Environment Identity v1

**Included:**
- `railverdict_version` (RailVerdict::VERSION)
- `ruby_engine` (RUBY_ENGINE)
- `ruby_version` (RUBY_VERSION)
- `analyzer_versions` (sorted map of enabled analyzers' versions, `unknown`-excluded, relevance-filtered)

**Excluded:** hostname, PID, username, time, absolute path, temp dir, CI job ID, CPU model, filesystem path, random seed, machine ID, RUBY_PLATFORM, Bundler version, OS/arch – breaks portability without trust gain.

Digest: `sha256(canonical_json{railverdict_version, ruby_engine, ruby_version, analyzer_versions})`. Deterministic, clone-independent.

Probes: lightweight `--version` via `ProcessRunner` (5s timeout, 64 KiB, no suite execution). SimpleCov without coverage file is skipped; non-required analyzer failures are skipped; required failures → `unavailable`.

## 5. Canonical Verification Identity

`VerificationIdentity` = `RepositoryState` + `VerificationEnvironment`, both captured via `Check.effective_input_paths` (honors `config`/`baseline`/`waivers` overrides). Digest over `{repository_digest, environment_digest}`. CLI `receipt verify` and MCP `get_verification_receipt`/`get_pr_intelligence` and `Cache` all delegate to `Receipt.validate_freshness` / `Receipt.evaluate`, which re-observes both dimensions and never trusts receipt-provided values as current.

## 6. Freshness state machine

`fresh` – current observable identity equals verified identity, all bound digests equal.
`stale` – at least one reason in `[head_changed, index_changed, worktree_changed, configuration_changed, baseline_changed, waivers_changed, railverdict_version_changed, ruby_engine_changed, ruby_version_changed, analyzer_environment_changed]`.
`invalid` – `receipt_malformed`, `receipt_too_large`, `incompatible_receipt_version`, `receipt_schema_invalid`, `receipt_integrity_failed`, `receipt_unreadable`.
`unavailable` – `repository_state_unavailable:*`, `analyzer_version_unobservable:*`, `environment_capture_failed:*`.

`fresh` ≠ `PASS`. A fresh `FAIL` remains a verified rejection; a fresh `INCOMPLETE` cannot become `PASS`.

## 7. Analyzer observation

Version probes only (`rubocop --version`, `rspec --version`, `bundler-audit version`, `ruby -rminitest -e "puts Minitest::VERSION"`). Bounded via `ProcessRunner` (timeout, max bytes, pgroup cleanup). No `rspec` suite, no `rubocop` run, no coverage generation. Fallback to direct executable when `bundle exec` fails in cloned fixtures without bundle install. SimpleCov skipped when coverage absent. Required analyzer probe failure → `unavailable`, never `fresh`.

## 8. CLI behavior

- `railverdict receipt create` – includes `ruby_engine`, excludes `unknown` analyzer versions, deterministic `receipt_id`.
- `railverdict receipt verify PATH [--config PATH] [--baseline PATH] [--waiver PATH]` – re-observes `RepositoryState` and `VerificationEnvironment` via `Check.effective_input_paths`; reports `status`, `reasons`, `gate`, `completion_status`, `current_repository_digest`, `current_environment_digest`; exit 0 `fresh`+`PASS/WARN`, 1 `fresh`+`FAIL`, 2 otherwise (stale/invalid/unavailable/incomplete).

## 9. MCP behavior

- `verify` – one `Check.execute_with_state_guard`, stores outcome + `receipt` + `pr_intelligence` with `state_digest` + `environment_digest`.
- `get_verification_receipt` / `get_pr_intelligence` – re-observe `RepositoryState` + `VerificationEnvironment` (lightweight probes), compare both digests; stale → `verification_required` with `stale` code, never return stale evidence as `fresh`; custom paths via same `Check.effective_input_paths`.
- Analyzer execution count = 1 per `verify`; version probes are not analyzer runs.

## 10. Repair hardening

RVLAB-16 fixed: waiver injection after a blocking finding now returns `gate: PASS` (honest current policy) but `target_status: still_present`, `verification_boundary_changed: {waivers: true}`, `overall_status: boundary_changed`. `successful` requires `target_status: fixed` + `PASS/WARN` + `!regressed` + `!boundary_changed`. Boundary cheating can never be `successful`. `gate` is not falsified.

## 11. Compatibility

1.2 receipts without `ruby_engine` remain structurally valid (schema allows missing engine) but are `stale`/`unavailable` under the stronger check when the current environment differs – intentional, prefer `stale` over `invalid`. Receipts with `analyzer_versions: {x: "unknown"}` are `unavailable` (fail-closed). `receipt_id` for new receipts includes `ruby_engine`; old receipts' IDs remain valid.

## 12. Determinism

Repository digest, environment digest, receipt_id, canonical JSON, and stale reason ordering are deterministic across repeated runs and clones. Absolute path, duration, PID, time are excluded. Tested via `test_determinism` and 20-run invariance.

## 17. Known limitations

- SimpleCov without coverage file is skipped (not version-checked); if SimpleCov is the only enabled analyzer and coverage is absent, environment has no analyzer versions → `fresh` may hide a SimpleCov version change (accepted: SimpleCov version is about gem, not coverage file, and coverage file absence is not a version signal).
- `ruby_engine` missing in 1.2 receipts is not automatically `stale`; only checked when present (backward compat). Future receipts will always include it.
- No cryptographic signatures; `receipt_id` is content identity only (per 1.2 trust model).
