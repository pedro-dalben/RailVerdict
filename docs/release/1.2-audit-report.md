# RailVerdict 1.2.0 — Independent Audit Report

Release under audit: `rail_verdict` 1.2.0 "Agent Verification Protocol"
Branch: `feat/1.2-agent-verification-protocol`
Audit scope: the entire 1.2 diff against 1.1.0 master (`ddbe303..HEAD`) and its direct dependencies.
Method: each cycle was executed by an independent auditor agent that did not author the implementation, working read-only over the real repository with live CLI probes (stub analyzers on PATH), scratch Git repositories, and full-suite runs.

## Audit Cycle 1

**Scope reviewed:** commits `ddbe303..d8333ed` (Repository State Identity v1, Verification Receipt v1, snapshot guard, receipt CLI, MCP tools + shared cache identity, schemas, docs, tests).

**Result: FAIL (release gate).**

| Severity | Count | Summary |
|---|---:|---|
| P0 | 0 | — |
| P1 | 1 | F-1 |
| P2 | 1 | F-2 |
| P3 | 6 | F-3..F-8 |

- **F-1 (P1): Guard bound DEFAULT input paths; effective inputs escaped identity.** `execute_with_state_guard` captured state over `.railverdict.yml`/default baseline/waiver paths while `Check.execute` consumed configuration-declared `baseline.path`/`waivers.path` and CLI overrides. Auditor demonstrated a live false-fresh PASS: out-of-root or gitignored waiver suppressed findings without appearing in `repository_state.waivers_digest`; `receipt verify` then reported fresh on unchanged tree.
- **F-2 (P2):** TOCTOU snapshot limits undocumented (within-capture composition; mutate-and-revert inside one guarded run).
- **F-3..F-8 (P3):** porcelain v2 awk-split fragility; loose digest patterns for index/worktree/configuration digests in schema; lexical-only CLI path containment vs symlink-aware MCP; narrow rescue in `RepositoryState.capture`; doc wording nit + dead test scaffolding.

**Remediations (commit `df363ea`, plus `8ca3359` follow-up):**
- Effective-input resolution (`Configuration.load` → `Baseline.resolve_path`/`WaiverStore.resolve_path` honoring overrides) now feeds BOTH guard captures; exposed as public `Check.effective_input_paths` and reused by `receipt verify` for symmetric freshness resolution.
- `PathSafety` module (deepest-existing-ancestor realpath containment) adopted by CLI create/verify and MCP `RepositoryRoot.contained?`; create rejects escaping `--config/--baseline/--waiver` before execution.
- Explicit single-space porcelain v2 field scanner; empty prefix fields fail closed; XY validation includes porcelain dots.
- Schema digest fields tightened to `sha256:` pattern; capture rescue broadened to fail closed on unexpected Errno/StandardError; ADR 0016 documents snapshot non-linearizability limits; contracts wording fixed.
- Regression tests: gitignored/config-declared input binding, containment rejection, silent-exit analyzer crash.

## Audit Cycle 2

**Scope:** remediated tree at `df363ea`.

**Result: PASS (release-gate question), one new P2.**

All cycle-1 items verified fixed empirically (including re-running the exact cycle-1 exploit: config-declared out-of-root waiver is content-bound into the receipt and its mutation flips fresh→stale `waivers_changed`). Suite: 510 runs / 0 failures. New finding:

- **N-1 (P2): verify-side containment asymmetry.** `receipt verify --baseline/--waiver` overrides bypassed containment; a fraudulent verify with out-of-root original content could mask staleness.

**Remediation (commit `8ca3359`):** both verify overrides routed through `resolved_override_path`; regression test added (`test_verify_rejects_out_of_root_input_overrides`). Full suite re-run: 511 runs / 0 failures.

## Audit Cycle 3 (Final)

**Scope:** `8ca3359`.
