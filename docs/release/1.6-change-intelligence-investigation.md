# 1.6 Change Intelligence — Stage 0 Investigation

Source inspected: RailVerdict 1.5.0 (`RailVerdict/lib`, `schemas/`, `lab/`).

## What PR Intelligence already knows

`RailVerdict::PRIntelligence.document(outcome)` (schema `pr-intelligence-v1`,
`SCHEMA_VERSION = "1.0"`) already produces, deterministically:

- `provenance`: head / base / merge_base / configuration_digest.
- `gate_result`: completion_status, gate, policy_status, findings summaries,
  operational_failures, decision_reasons.
- `change`: files_changed, lines_added/removed (nil-safe), status_counts
  (added/modified/deleted/renamed).
- `signals` (6, each with evidence + truncation count):
  `database_change` (db/schema.rb, db/structure.sql, db/migrate/),
  `routes_change`, `dependency_change` (Gemfile, Gemfile.lock),
  `configuration_change` (config/), `authorization_change` (app/policies/),
  `tests_change` (spec/, test/).
- `quality_delta`: introduced / existing / resolved / changed / moved /
  waived / orphaned_waivers (fail-closed when baseline missing/incompatible).
- `analyzer_evidence`: per-analyzer execution_status + evidence_status.
- `test_intelligence`: minitest/rspec totals, failures, errors, runner.
- `coverage`: global percent + changed-lines percent/covered/executable.

Supporting primitives (all working, reused as-is):

- `Git::Context`: changed files (status, old/new path, score, binary,
  lines_added/removed), changed_line_set, binary/conflicted paths, rename_map.
- `RailsContext::Classifier`: model/controller/job/mailer/helper/service/
  policy/component/view/route/schema/migration/test/spec/config/lib/unknown.
- `RailsContext::Context`: changed-scope Rails entries + unresolved reasons
  (`dynamic_dsl`, `structure_sql_not_parsed`).
- `TestSelection.resolve`: targeted vs full + selected_files + fallback_reason
  (`shared_infrastructure_changed:*`, `unmapped_source_change:*`,
  `unrecognized_source_file:*`, `no_candidate_tests_found`,
  `empty_or_unresolvable_changed_scope`).
- `VerificationPlan`: test_scope, target_files, fallback_reasons per framework.
- RSpec/Minitest `evidence_summary` already carries `test_scope`,
  `target_files`, `fallback_reason` for executed runs — verification scope is
  observable post-hoc without new plumbing.
- `Comparison`: introduced/existing/resolved/changed/moved/waived counts.
- `GateResult`: completion/gate/policy coupling enforced; intelligence never
  touches it (invariant holds structurally — separate module, read-only input).
- MCP `get_pr_intelligence` + CLI `railverdict pr` + receipt embedding all call
  `PRIntelligence.document(outcome)` — one canonical builder, parity by
  construction if extended in place.
- Config: versioned schemas through 1.5; `review:` section does not exist yet.

## What data is missing for 1.6

1. Rails change surfaces beyond the 6 signals (authentication, migration vs
   schema split, public API, jobs, models/controllers/views/mailers/storage,
   initializers, security/credentials, test infra, shared infra).
2. Project-defined sensitive areas (`review.sensitive_paths`) — no config.
3. Explainable review risk — nothing aggregates signals into LOW/MEDIUM/HIGH/
   CRITICAL with reasons.
4. Executed verification scope in the intelligence document (FULL vs TARGETED,
   selected files, fallback reason) — present in analyzer evidence, not
   projected into PR Intelligence.
5. Missing-evidence facts (auth changed but no deterministic test mapping,
   stale coverage, incomplete required analyzers, ambiguous targeted mapping).
6. Ordered Review Focus list.
7. Human CLI summary for `check --changed` (console reporter shows gate +
   counts but no risk/surfaces/focus).

## Derivable deterministically

- All path-convention surfaces (migration, routes, dependencies, schema,
  models/controllers/views/mailers/jobs prefixes, initializers, storage,
  credential paths, shared base classes, test helpers) from
  `git_context.changed_files` paths.
- Sensitive defaults + project globs via `File.fnmatch`.
- Risk = max over policy-driven per-signal levels with reason codes.
- Verification scope from `evidence_summary.test_scope/target_files/
  fallback_reason` + `TestSelection.resolve` recompute when analyzer absent.
- Missing evidence from analyzer execution_status + required flags +
  fallback reasons + coverage/baseline availability.
- Review focus = priority-ordered changed surfaces with evidence.

## Requires heuristics (explicitly classified)

- `authentication` (sessions/devise filename conventions), `public_api`
  (`app/controllers/api/**` implies public exposure — heuristic), and the
  `security` name-pattern tier (secret/csp/ssl initializer names). Each
  emitted with `"detection": "inferred"` and documented reason; strong
  conventions (`app/policies/**`, devise initializer, credential files) are
  `"detected"`.
- Semantic claims (e.g. "no authorization tests exist", tenant isolation,
  payment-area meaning) are NOT derivable — reported as UNKNOWN / not
  established, never as fact.

## Requires AI (out of scope, not implemented)

- Business-logic explanation, semantic blast-radius ("this service affects
  billing"), natural-language review comments, productivity claims. 1.6 ships
  no AI signals; `intelligence/` (explain) remains advisory-only and disjoint
  from GateResult and Change Intelligence.

## Architecture decision (Stage 0 verdict)

- Evolve `PRIntelligence` in place to schema `1.1` (new sections appended;
  all v1.0 keys unchanged) — no parallel document type. New schema file
  `pr-intelligence-v1.1.schema.json`; v1.0 file frozen for old receipts.
- New modules: `change_surfaces.rb` (surface table + detection + sensitive
  matching) and `change_intelligence.rb` (risk, verification_scope,
  missing_evidence, review_focus assembly). `PRIntelligence.document` merges
  their output — CLI (`pr`), MCP (`get_pr_intelligence`), and receipts share
  the canonical model with zero duplicated logic.
- Config `1.6` adds optional `review:` (`sensitive_paths`, `risk` overrides);
  1.5 configs keep working.
- A generalized risk engine is REJECTED as overkill; a policy-driven
  max-severity aggregation with reason codes is sufficient (Stage 3 resolved).
