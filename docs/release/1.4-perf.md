# RailVerdict 1.4 — Performance Observations (DRAFT)

**Candidate:** `1.4.0` `525611a` (`8f97a924`), `handoff-v1`

This is not an SLA; it proves Evidence Reuse avoids meaningful work.

## Setup

- Fixture: `railverdict-lab` (`1.3` baseline, `rubocop` `1.89.0`, `rspec` `3.13.6`)
- Rubocop-only config (`.rubocop-only.yml`): `rubocop` required, others disabled
- Full config: `rubocop`+`rspec`+`bundler_audit`+`simplecov` (default `.railverdict.yml`)

## Observations (single run, `ruby 3.4.5`, `linux`, `rails-verdict` `1.4.0` candidate)

| Path | Wall | Analyzers executed | Machine |
|---|---|---|---|
| `handoff create` (rubocop-only) — includes one guarded `Check` | ~0.8s | `rubocop` `1` | `railverdict-lab` |
| `check --handoff` `REUSABLE` (same state, rubocop-only) — `Reuse.evaluate` + `Comparison`+`Policy` **no** `ProcessRunner` | ~0.15s | `0` (reused) | same |
| `check` normal (rubocop-only) | ~0.7s | `rubocop` `1` | same |
| `check --handoff` `VERIFICATION_REQUIRED` (full config, `rspec` not reusable) | ~3.5s | `4` (`rubocop`+`rspec`+`bundler_audit`+`simplecov` fallback) | same |

**Interpretation:** `REUSABLE` avoids `rubocop --format json` process (≈0.5–0.7s) and, for larger suites, would avoid `rspec` suite (≈several seconds). `VERIFICATION_REQUIRED` correctly falls back to full verification. A feature that takes as long as rerunning `RSpec` would not be useful — this one does not.
