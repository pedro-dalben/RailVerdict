# 1.6 Change Intelligence — Implementation Report

## Architecture decision
Evolved `PRIntelligence` in place (schema `1.0` → `1.1`, all v1.0 keys
byte-identical) instead of a parallel document type. New modules:
`ChangeSurfaces` (19 path-convention surfaces + project globs) and
`ChangeIntelligence` (signals, risk, verification scope, missing evidence,
review focus). `PRIntelligence.document` merges them, so CLI `pr`, MCP
`get_pr_intelligence`, and receipt embedding share one canonical builder with
zero duplicated logic. The generalized risk engine was rejected as overkill;
max-severity aggregation over policy-driven levels won (Stage 3 resolved).

## PR Intelligence migration
- `SCHEMA_VERSION = "1.1"`; v1.0 schema file frozen (old receipts still
  validate via version-dispatched `validate_pr_intelligence`).
- New sections: `surfaces`, `project_sensitive_areas`, `review_signals`,
  `review_risk`, `verification_scope`, `missing_evidence`, `review_focus`.
- `stable_projection` untouched; new sections are deterministic functions of
  the same inputs, so receipt binding stays stable.
- Defensive `respond_to?` guards for duck-typed outcomes (tests, MCP cache).

## Surfaces (19)
security(mixed) authorization authentication(inferred) migration database
dependencies public_api(inferred) routes background_jobs controllers models
views mailers storage initializers configuration test_infrastructure
shared_infrastructure — each with evidence (cap 20), tier, and sensitive flag.

## Signals / risk
Codes: `security_config_changed`, `authorization_surface_changed`,
`authentication_surface_changed`, `migration_added`,
`database_surface_changed`, `dependency_changed`, `public_api_changed`,
`routes_changed`, `shared_infrastructure_changed`, `configuration_changed`,
`project_sensitive_path_changed:<name>`. Defaults: security critical;
authorization/authentication/migration high; database/dependencies/public_api/
routes/shared_infra/configuration medium. Overall = max, reasons sorted.
`review.risk` overrides per surface; project areas default high.

## Quality delta
Unchanged v1.0 behavior (introduced/existing/resolved/changed/moved/waived/
orphaned, fail-closed without baseline), now adjacent to focus/scope output.

## Verification scope
Executed analyzer evidence (`test_scope`/`target_files`/`fallback_reason`)
wins per framework; absent analyzers fall back to a deterministic
`TestSelection.resolve` recompute marked `executed: false`. Trust-critical
FULL-vs-TARGETED distinction explicit in CLI, JSON, and MCP.

## Review Focus
Priority-ordered changed surfaces with rank/reason/evidence (cap 10+count);
non-sensitive items fully covered by higher-ranked items are skipped
(sensitive items and project areas always shown); project areas appended.
Console prints titles only (bounded); JSON has paths.

## CLI UX
`pr` console: risk, sensitive surfaces, verification scope, missing evidence,
reviewer focus. `check --changed` console: compact risk/sensitive/tests/focus.

## Machine schema / MCP
`schemas/pr-intelligence-v1.1.schema.json` (16 required top-level keys);
`configuration-v1.6.schema.json` (`review.sensitive_paths`, `review.risk`).
MCP: same document, description updated, no new tools.

## Agent experiment
A/B on a synthetic auth+migration change, two isolated agents. Control
(diff only) prioritized by diff size (model first) with vague "no tests"
completeness. Intelligence-fed agent led with Authorization + Migration as
HIGH risk drivers and named the exact gaps (full suite not executed, auth
mapping unestablished). Observed benefit: correct prioritization + specific
completeness judgment. Limitations: n=1, synthetic, same model family —
exploratory, no productivity claim.

## False-confidence audit
- Generic service with access logic → authorization NOT claimed, risk LOW.
- Renamed policy → detected via old+new paths.
## Remaining limitations

3. Focus dilutes on mega-diffs (by design; caps hold).
4. `lab/ci-*` branches + catalog/candidate edits unpushed (no auto-publish).
