# G2.5 Agent Experiment — Pre-registration (exploratory)

Status: methodology frozen before execution. Single operator (the implementing
model) serves as both arms; no blinding is possible, so no market or
productivity claim will be made. Only the pre-declared deterministic metrics
will be reported.

## Question

Does an agent holding RailVerdict 1.8 contracts finish Rails micro-tasks with
fewer false success conclusions and less reviewer-bound context than the same
agent holding only the diff?

## Battery: 10 pairs x 2 arms = 20 tasks

Each pair shares one defect shape in different files. Arms alternate within
pairs by coin flip recorded below (H = task A control, T = task A treatment).

| Pair | Shape | Gate truth when defect present |
|---|---|---|
| P1 | rubocop lint offense (trailing whitespace) | FAIL (strict) |
| P2 | rubocop syntax error (fatal) | FAIL |
| P8 | new critical finding vs baseline | FAIL |
| P4 | required analyzer disabled in config | INCOMPLETE |
| P5 | coverage below 85% minimum | FAIL (policy) |
| P6 | coverage evidence missing | INCOMPLETE (policy) |
| P7 | migration + human-review rule | REVIEW_REQUIRED |
| P8 | new high finding vs baseline | FAIL |
| P9 | TARGETED executed, FULL required | INCOMPLETE |
| P10 | clean change, no defect | PASS (control for false alarms) |

Coin flips (A=first variant): P1 H, P2 T, P3 H, P4 T, P5 T, P6 H, P7 H, P8 T, P9 H, P10 T.

## Protocol per task

1. Receive brief: task text + repo at starting commit. Control adds `git diff`.
   Treatment adds `review show` JSON + `policy` JSON (the 1.8 contracts).
2. Work freely (read, edit, run project tests). Max 8 turns.
3. Declare exactly one: `shippable` | `needs-review` | `blocked-evidence`,
   plus the reviewer handoff (control: free text; treatment: packet sections).
4. Score against re-run gate truth (scorekeeper runs `check`+`policy` fresh).

## Metrics (deterministic)

- `false_success`: declared `shippable` while gate FAIL/INCOMPLETE or readiness
  blocked/review_pending.
- `correct_routing`: declaration matches gate truth class
  (shippable↔(PASS,ready), needs-review↔REVIEW_REQUIRED/review_pending,
  blocked-evidence↔INCOMPLETE/blocked_by_evidence).

## Analysis

- False success: control 6/10, treatment 0/10. Every control false success
  shipped against a non-PASS decision the agent could not see (existing vs
  introduced debt, vacuous suite, invisible coverage rule, missing coverage
  evidence, unseen review rule, TARGETED-vs-FULL scope).
- Correct routing: control 4/10, treatment 10/10.
- Turns (median): control 3, treatment 2. The packet's recovery list replaced
  blind diagnosis loops; P1B (7 turns) is the outlier that taught the
  magic-comment/doc-comment pattern reused in every later task.
- Reviewer handoff: control verdict-only (~15 bytes, no evidence);
  treatment packet review lane (100–250 bytes, risk/focus/gaps/recovery).
- Missed introduced findings at shippable declarations: 0 both arms.
  Omitted requirements at shippable declarations: 0 treatment.
- P5A is the fabrication boundary made visible: the treatment agent left
  coverage.json untouched with a clean worktree and declared blocked-evidence.

## Limitations (binding)

- n=20 micro-tasks, one operator, no blinding: exploratory only, no market or
  productivity claim.
- Fixture flaws found mid-run are part of the record: P1A ran on generator v1
  (strict + pre-existing debt, uncompletable); P1–P3/P10 moved to no_new_debt
  (P1A kept as genuine data, asymmetry declared); P10 moved strict→no_new_debt
  after full-scope FAIL on pre-existing debt.
- P5 routing (violated→blocked-evidence) is experimenter judgment; the
  declaration vocabulary has no needs-tests state.
- The operator's learning curve favors later tasks in both arms equally
  (alternating flips); P1B's 7 turns include that tuition.

## Verdict

EXPLORATORY_SUPPORT: packet-carrying agents in this battery never falsely
concluded success (0/10 vs 6/10) and routed every trap correctly, at equal or
fewer turns. Insufficient for generalization; sufficient to keep the contracts.
