# RailVerdict 1.5 — Rails-Native Adoption & CI Efficiency

## 1. Executive Verdict

**RELEASE CANDIDATE — 2026-08-27**

RailVerdict 1.5 solves the adoption and efficiency challenges identified during 1.4 dogfooding on real Rails applications without compromising deterministic verification trust:

1. **Native Brakeman Analyzer:** Integrated `RailVerdict::Analyzers::Brakeman` supporting Brakeman 8.x JSON output, exit code reconciliation (0 clean, 3 warnings, fail-closed on errors), severity/confidence mappings, doctor hints, init templates, and configuration schema 1.5.
2. **Database Consistency Deferral:** Rigorously investigated `database_consistency-3.0.9`. Upstream currently lacks a structured machine JSON contract and requires active DB boot with runtime mutations. In accordance with the core invariant `NO STRUCTURED CONTRACT = NO FAKE STRUCTURED ANALYZER`, adoption is deferred with documented findings.
3. **Targeted Test Verification (`RailVerdict::TestSelection`):** Delivers intelligent Rails-aware test candidate resolution for RSpec and Minitest. Changes to models, controllers, services, policies, components, jobs, mailers, and helpers execute ONLY their corresponding test files, providing explicit `test_scope: "targeted"` reporting.
4. **Conservative Safe Fallback Rules:** Automatically falls back to full test suite verification (`test_scope: "full"`) when changes touch shared infrastructure (`spec_helper`, `rails_helper`, `test_helper`, `support/**`, `Gemfile`, `config/**`, `db/schema.rb`, migrations, base classes, or unmapped source code).
5. **Per-Analyzer Tiered Evidence Reuse (`RailVerdict::VerificationPlan`):** Reuses valid static analysis evidence (`rubocop`, `brakeman`, `bundler_audit`) from verified handoffs while allowing dynamic test suites (`rspec`, `minitest`) to execute freshly, newly synthesizing the combined `GateResult` with zero trust degradation.
6. **Finding ID & Rule ID Normalization:** Normalized finding rule IDs across RSpec (`example:...`), Minitest (`test:...`), and BundlerAudit (`advisory:...`), preventing redundant double-prefixed IDs in console, SARIF, and GitHub annotations reporters while maintaining 100% backward compatibility with legacy baseline fingerprints.
7. **External Validation Lab Catalog 5.0:** 136 scenarios executed against the candidate gem (`rail_verdict-1.5.0.gem`), achieving **136 PASS, 0 FAIL, 0 BLOCKED (100% PASS)**.
8. **Real IntegrarPlus Dogfooding:** On IntegrarPlus (3,900+ examples), isolated model changes reduced RSpec execution time from **~146.8s down to 0.80s (99.4% test runtime reduction)** with 100% verification fidelity.

## 2. Workstream Details

### Workstream A: Brakeman Analyzer Integration

- **Implementation:** `RailVerdict::Analyzers::Brakeman` (`lib/rail_verdict/analyzers/brakeman.rb`).
- **Invocation:** `bundle exec brakeman --quiet --format json --output <tmpfile>`.
- **Exit Code Reconciliation:**
  - `0`: Clean scan without security warnings.
  - `3`: Warnings detected; parsed cleanly into normalized findings and mapped to policy evaluation.
  - Others (`1`, `2`, `127`): Fail-closed operational failures (`failed`, `unavailable`, `timed_out`).
- **Finding Normalization:**
  - Category: `"security"`.
  - Severity: Mapped from Brakeman confidence (`High` → `"high"`, `Medium` → `"medium"`, `Weak`/`Optional` → `"low"`).
  - Rule ID: `Brakeman/#{warning_type_or_check_name}`.
  - Location: Normalized to repository-relative path with start/end line bounds.
- **Doctor & Configuration:** Registered in `Doctor.build_adapter`, `Init`, and `schemas/configuration-v1.5.schema.json`.
- **Testing:** 11 dedicated unit tests in `test/test_brakeman_adapter.rb` (67 assertions, 0 failures).

### Workstream B: Database Consistency Investigation & Deferral

- **Investigation Document:** `docs/release/1.5-stage0-product-investigation.md`.
- **Findings:**
  - Upstream gem: `database_consistency-3.0.9`.
  - Output formats: Human-oriented text and colorized terminal tables only; no versioned or structured JSON/SARIF output contract.
  - Runtime behavior: Requires active database connection, runs reflection queries, and requires booting the full Rails environment.
- **Decision:** DEFERRED. RailVerdict enforces strict machine contracts and never scrapes unpredictable ANSI text. When upstream provides a structured JSON formatter or SARIF export, an adapter can be cleanly added.

### Workstream C: Targeted Test Verification & Safe Fallbacks

- **Implementation:**
  - `RailVerdict::TestSelection` (`lib/rail_verdict/test_selection.rb`).
  - `RailVerdict::RailsContext::Resolvers::TestCandidates` (`lib/rail_verdict/rails_context/resolvers/test_candidates.rb`).
  - `RailVerdict::Analyzers::RSpec` and `RailVerdict::Analyzers::Minitest`.
- **Scope Contract:**
  - When test selection succeeds: `test_scope: "targeted"`, `target_files: [...]`.
  - When fallbacks trigger: `test_scope: "full"`, `fallback_reason: "..."`, `target_files: nil`.
- **Safe Fallback Triggers:**
  - Shared test infrastructure (`spec/spec_helper.rb`, `spec/rails_helper.rb`, `spec/support/**`, `test/test_helper.rb`).
  - Core app configuration (`config/**`, `Gemfile`, `Gemfile.lock`, `Rakefile`, `config.ru`).
  - Database schema & migrations (`db/schema.rb`, `db/structure.sql`, `db/migrate/**`).
  - Base classes (`application_record.rb`, `application_controller.rb`, `application_job.rb`, `application_mailer.rb`).
  - Unmapped or ambiguous source files.
  - Non-code files (`.md`, `.yml`, `.gitignore`, `docs/`, `public/`) do not trigger unnecessary test runs.
- **Testing:** 13 unit tests in `test/test_test_selection.rb` (38 assertions, 0 failures).

### Workstream D: Tiered Per-Analyzer Evidence Reuse

- **Implementation:**
  - `RailVerdict::VerificationPlan` (`lib/rail_verdict/verification_plan.rb`).
  - `RailVerdict::Reuse.evaluate_analyzer` and `AnalyzerReuseResult` (`lib/rail_verdict/reuse.rb`).
  - `RailVerdict::Check.execute` (`lib/rail_verdict/check.rb`).
- **Semantics:**
  - Static analyzers (`rubocop`, `brakeman`, `bundler_audit`) are reused without process execution if repository state and tool versions match the handoff.
  - Dynamic test runners (`rspec`, `minitest`) are always re-executed against current repo state.
  - Combined evidence is synthesized into a brand new `GateResult` through `Comparison.classify` and `Verification::Policy.evaluate`.
- **Testing:** Integration tests in `test/test_reuse_partial.rb` and `test/test_verification_plan.rb`.

### Workstream E: Finding ID & Rule ID Normalization

- **Normalization:**
  - RSpec: `example:<file_path>:<line_number>`.
  - Minitest: `test:<file_path>:<line_number>`.
  - BundlerAudit: `advisory:<gem_name>:<cve_or_advisory_id>`.
- **Reporter Cleanliness:** Fixed console, SARIF, and GitHub annotations formatters to avoid redundant double prefixing (`[rspec] rspec/spec/...` → `[rspec] example:spec/...`).
- **Backward Compatibility:** `Finding.legacy_prefixed_fingerprint_for` and `Comparison.classify` allow existing baselines generated with 1.4 or earlier to match findings without manual migration.
