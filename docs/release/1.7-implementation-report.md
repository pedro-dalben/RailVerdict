# 1.7 Engineering Policy — Implementation Report

## Architecture decision
Kept the deterministic verdict intact and added a separate versioned envelope
(`engineering-policy-v1`) instead of widening `result-v1`, `pr-intelligence-v1.1`,
receipt v1, or handoff v1 (ADR 0020). New module `EngineeringPolicy` (planner +
evaluator) reads the decided `GateResult` plus the canonical 1.6 intelligence
document; CLI `policy` and MCP `get_engineering_policy` share the single service.
Pending human review surfaces as `REVIEW_REQUIRED` (exit 3) — never silent `PASS`,
analyzer `FAIL`, or fabricated approval. SARIF stays findings-only by design.

## Contracts
- `schemas/configuration-v1.7.schema.json`: additive `engineering_policy`
  section (`findings`, `coverage`, `changes`, `review`); closed, bounded, enums.
  Configs 1–1.6 validate and behave identically.
- `schemas/engineering-policy-v1.schema.json`: envelope with deterministic
  requirement identities (`req-<kind>-<key>`, sorted), reason codes, digests.
- `policy_digest` (canonical policy JSON) + `configuration_digest` (config bytes);
  `policy --receipt/--handoff` reports `fresh`/`policy_drift`/`unavailable`
  without relabeling v1 documents. Old receipts never satisfy new rules.

## Semantics (all covered by tests + Lab)
Required analyzer missing → `INCOMPLETE`; stale/missing coverage → `INCOMPLETE`;
valid coverage below minimum → `FAIL`; forbidden new finding → `FAIL`;
FULL-required but TARGETED-executed → `INCOMPLETE` with re-run recovery;
human review triggered → `REVIEW_REQUIRED`; untriggered rule → `not_applicable`;
unknown/ambiguous/oversized config → rejected; rule order never changes the digest.

## Adversarial notes
Forged approvals have no input channel (evaluator takes no review document);
`TARGETED`-labeled-`FULL` without execution is rejected; policy drift after
receipt is `policy_drift`, never PASS; analyzer success without complete evidence
is `unavailable`; AI review has no status-changing path by construction.

## Limitations
- Review-approval presence has no verifiable proof; `REVIEW_REQUIRED` clears only
  when the trigger goes away (ADR 0020 Deferred Work).
- Changed-lines coverage needs fresh SimpleCov evidence; lab crafting showed real
  RSpec runs regenerate `coverage/coverage.json` (argv-level side effect all
  interfaces share) — scenarios pin the v1 shape explicitly.
- Intelligence stays path-convention heuristics (1.6 limits inherited).
- IntegrarPlus full-suite dogfooding not repeated (shared-database risk, G0 rule).
