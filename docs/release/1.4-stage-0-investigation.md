## 1. Current architecture map (1.3 as observed)

Inspected code paths (file:line authoritative):

- `lib/rail_verdict/check.rb` — `Check.execute` / `execute_with_state_guard`. Captures `pre`/`post` `RepositoryState` via `RepositoryState.capture`, runs `RunContext.from_configuration`, executes analyzers via `Analyzers::Runner`, collects `AnalyzerResult[]`, applies baseline/waiver/policy via `Comparison`/`Baseline`/`WaiverStore`, produces `GateResult` ( `lib/rail_verdict/comparison.rb`, `baseline.rb`, `configuration.rb` ).
- `lib/rail_verdict/run_context.rb:1` — immutable `RunContext` (mode, analyzers enabled/required, thresholds, timeouts, changed scope, paths). Derived from `.railverdict.yml` via `Configuration`.
- `lib/rail_verdict/repository_state.rb:1` — canonical `RepositoryState` over `head`, `index_digest` (`git ls-files -s`), `worktree_digest` (porcelain v2 + per-path content hashes), `configuration_digest`, `baseline_digest`, `waivers_digest`. Deterministic `sha256:`, bounded, portable, fail-closed on unavailable. Respects `Check.effective_input_paths` for custom config/baseline/waivers.
- `lib/rail_verdict/verification_environment.rb:1` — canonical `VerificationEnvironment` over `railverdict_version`, `ruby_engine`, `ruby_version`, sorted `analyzer_versions` (unknown-excluded, relevance-filtered). Probes via `ProcessRunner` `--version` (5s, 64KiB), no suite execution.
- `lib/rail_verdict/verification_identity.rb:1` — `VerificationIdentity = {repository_digest, environment_digest}` deterministic `sha256:` over canonical JSON.
- `lib/rail_verdict/receipt.rb:1` — `Receipt.build` (pre/post guard, `repository_changed_during_verification`), `Receipt.parse`, `Receipt.validate_freshness` / `Receipt.evaluate` — single canonical evaluator that independently re-observes `RepositoryState` + `VerificationEnvironment` via `VerificationIdentity`. Trust Invariant Zero: receipt-provided values never used as current observation. `receipt_id = sha256(canonical_json[payload])`, volatility excluded (duration, PID, time, path). Schema `verification-receipt-v1`.
- `lib/rail_verdict/pr_intelligence.rb` — deterministic projection over `GateResult` + git diff; advisory, never authoritative.
- `lib/rail_verdict/repair/` — `RepairPacket` v1 immutable `packet_id sha256:`, `Verifier` classification `fixed|still_present|changed|moved|regressed|incomplete`; `overall_status: boundary_changed` when `verification_boundary_changed` non-empty (RVLAB-16).
- `lib/rail_verdict/mcp/cache.rb` — stores `state_digest` + `environment_digest`; `get_verification_receipt`/`get_pr_intelligence` re-observe via same `Receipt.validate_freshness`, custom paths via `Check.effective_input_paths`.
- `lib/rail_verdict/configuration.rb`, `waiver_store.rb`, `baseline.rb` — policy surface: mode (advisory/no_new_debt/strict), analyzer enabled/required, severity thresholds, changed coverage policy, timeouts, changed/full scope.
- `lib/rail_verdict/analyzers/` — adapters: `rubocop`, `rspec`, `minitest`, `simplecov`, `bundler_audit`. Each produces `AnalyzerResult{analyzer, execution_status, tool_version, findings[]|coverage}`.

Data flow verified in `check.rb`:

```
configuration (.railverdict.yml + effective_input_paths)
  ↓
RunContext (immutable, analyzer set, mode, scope)
  ↓
RepositoryState.pre + VerificationEnvironment.current
  ↓
Analyzer execution (external, bounded ProcessRunner, owned reporters)
  ↓
Normalized evidence (AnalyzerResult + Finding[fingerprint/sha256] + coverage normalized)
  ↓
Baseline comparison (fingerprint exact, introduced/existing/resolved)
  ↓
Waiver evaluation (exact fingerprint, UTC expiry)
  ↓
Policy (thresholds, mode)
  ↓
GateResult {gate:PASS/WARN/FAIL/INCOMPLETE, completion_status, findings, analyzer_results, operational_failures, decision_reasons}
  ↓
(Receipt.build over repository_state + environment + gate_projection + PR stable digest + repair binding)
```

Evidence reuse insertion point (investigated, not yet implemented): reuse must enter **before** `GateResult` construction, feeding `previous normalized evidence` + `newly executed evidence` through the **same canonical comparison/policy pipeline** to produce a **new** GateResult. Old GateResult must never become second source of policy authority.

## 2. Trust layers

Layered model derived from 1.3 `Receipt` and `VerificationIdentity`:

1. **Repository State Identity** — HEAD, index, worktree, config/baseline/waivers digests. Observability: `git` + file hashes. Bound, deterministic.
2. **Verification Environment Identity** — railverdict_version, ruby_engine, ruby_version, relevant enabled analyzer versions. Observability: `ruby --version`, `RUBY_ENGINE`, `ProcessRunner` `--version` probes. Fail-closed on `analyzer_version_unobservable`.
3. **VerificationIdentity** — composition of (1)+(2). Basis for freshness.
4. **Evidence Provenance** — per-analyzer `tool_version`, execution_status, completeness, source scope, coverage producer linkage, advisory DB revision (bundler-audit).
5. **Policy/Baseline/Waivers** — current configuration, baseline file, waiver store. Deterministic but mutable; not part of receipt freshness directly except via repository_state digests for default paths, plus must be re-evaluated even when evidence reusable.
6. **Git/Source/Base scope** — full vs changed, base revision, merge_base, HEAD, index, worktree, untracked relevant state.
7. **Completeness** — required vs optional evidence, INCOMPLETE semantics.

Each layer independently contributes to reuse decision. Receipt freshness covers (1)+(2) via VerificationIdentity; evidence reuse requires (1)+(2)+(4)+(5)+(6)+(7).

## 3. Freshness vs reuse distinction

- **RECEIPT_FRESH** — the currently observable `VerificationIdentity` (repository_digest + environment_digest) equals the identity captured at verification time and bound in the Receipt. Proven by `Receipt.validate_freshness` re-observing state/environment and comparing digests/stale reasons. Freshness says: "same observable identity as before."

- **EVIDENCE_REUSABLE** — previous normalized evidence remains semantically sufficient under the **currently observed** repository state, verification environment, analyzer environment, dependency state, configuration, policy, baseline, waivers, Git/base scope, provenance, and completeness requirements, such that expensive producers need not re-execute. Reuse is stronger than freshness.

- **Relationship: `RECEIPT_FRESH != EVIDENCE_REUSABLE`**

  Freshness is **necessary** for reuse but not sufficient. Examples:
  - Fresh receipt + advisory DB changed → bundler-audit evidence not reusable.
  - Fresh receipt + policy `advisory→strict` → evidence may be reusable but old GateResult is not.
  - Fresh receipt + changed/base scope mismatch → changed-scope evidence not reusable.
  - Fresh receipt + missing required analyzer evidence → reuse unavailable.

  Similarly `EVIDENCE_REUSABLE != GATE_REUSABLE`. Reused evidence must still be evaluated by current policy/baseline/waivers to produce a new GateResult.

## 4. Evidence taxonomy

Distinguish raw vs normalized:

- **Raw analyzer output** —stdout/json from `rubocop --format json`, `rspec --format json`, `minitest` reporter, `simplecov_json_formatter`, `bundler-audit check --format json`. Unbounded, potentially large, not reused directly.
- **Normalized RailVerdict evidence** — `AnalyzerResult{analyzer, execution_status: success|incomplete, tool_version, findings[]|coverage}` where findings are `{analyzer, rule_id, path, message, fingerprint:sha256, location}` via `Fingerprint`/`Shared.normalize_finding_message`. Deterministic ordering, bounded messages, truncated/malformed handling preserved.

Taxonomy per analyzer:

- **RuboCop** — findings array, tool_version (rubocop + rubocop-rails provenance), source scope, config digest.
- **RSpec/Minitest** — findings (failures), execution_status, tool_version, suite completeness (zero-tests, truncated, etc.), not coverage.
- **SimpleCov** — normalized coverage `{files: {path: {lines:[int|null]}}, version, meta}`, provenance: requires test execution that produced it.
- **bundler-audit** — findings (advisories), tool_version, advisory DB revision (ruby-advisory-db), Gemfile.lock scope.

Evidence completeness: `INCOMPLETE` (unavailable, unsupported, timed_out, signaled, failed, parse_failed, truncated, malformed) never becomes PASS.

## 5. Reuse predicates by analyzer (analyzer-by-analyzer study)

### RuboCop — REUSABLE UNDER bounded equivalence

Necessary:
- Source identity equivalent (RepositoryState covers HEAD/index/worktree).
- Configuration identity equivalent (`.rubocop.yml`, inherited configs, `.railverdict.yml` rubocop enabled state, target Ruby version config, plugin inclusions). RepositoryState's `configuration_digest` via `Check.effective_input_paths` covers primary config; external `inherit_from` remains gap — fail-closed if unobservable external config appears outside repo? Current model: such external deps outside repo not hashed — predicate must be conservative: if RuboCop config references external or inherited files not under repo root, reuse fails closed (provenance_unobservable).
- Analyzer environment equivalent: `rubocop` version, `rubocop-rails` version, `ruby_engine`/`ruby_version` (target Ruby influences parsing), relevant Gemfile.lock not required beyond those versions unless config influences gem-loaded cops. Conservative: require `analyzer_versions[rubocop]` equality; railverdict_version equality (environment digest).
- No filesystem state beyond repo (RuboCop is file-content deterministic).
- No time dependency.

Sufficient under those bounds: previous normalized RuboCop findings remain valid. Reuse can avoid `rubocop --format json` process. Must still re-evaluate baseline/waivers/policy.

### RSpec — NOT REUSABLE (bounded assumptions insufficient)

Investigated dimensions: source/spec state, Ruby runtime, loaded dependency versions (Gemfile.lock, Rails version), ENV, test DB/schema, generated code, external services, random seed (`--seed`), filesystem state, nondeterministic tests.

Finding: RSpec evidence is **not safely reusable** in general via observable identity alone. Counterexamples:
- Same source + same Ruby + same analyzer_version but different `DATABASE_URL`/`RAILS_ENV` → different results unobservable via VerificationIdentity.
- Flaky/nondeterministic tests (`SecureRandom`, time, order-dependent state) → previous PASS not proof of current.
- DB schema/external service state not captured by RepositoryState/Environment.
- To declare RSpec reusable would require observing the entire test dependency closure (all installed gems, DB snapshot, ENV) — not bounded, not portable, not offline.

**Verdict: FAIL-CLOSED. RSpec evidence requires fresh execution. Reuse predicate `unobservable` → `VERIFICATION_REQUIRED`.** Future work could allow reuse only under explicit opt-in with additional declared test dependencies, but not in 1.4 default.

Same for **Minitest** — identical reasoning (different runner but same nondeterminism/dependency concerns). **NOT REUSABLE**.

### SimpleCov — NOT INDEPENDENTLY REUSABLE

Coverage depends on test execution that produced it. Even if source unchanged, stale coverage from previous run may not reflect current test suite results. If RSpec/Minitest evidence is not reusable, coverage evidence cannot be independently reused. Additionally `coverage.json` provenance (producer suite) must match current required test evidence.

**Verdict: NOT REUSABLE independent of test evidence. If per-analyzer reuse deferred, simplecov reuses iff tests reuse; but since tests don't, simplecov doesn't.**

### bundler-audit — REUSABLE ONLY WITH ADVISORY DB EQUIVALENCE

Dimensions:
- `Gemfile.lock` identity (repository state covers it via worktree digest).
- `bundler-audit` tool_version (captured in VerificationEnvironment).
- **ruby-advisory-db revision** — changes while source remains identical. Receipt freshness alone does NOT cover this. Must observe DB revision. Current product does not capture DB revision as part of environment digest; `bundler-audit` probes version but not DB timestamp/commit.
- Advisory DB freshness/update state — network-dependent, not offline-deterministic. Time alone not identity, but DB content is.

**Verdict: REUSABLE ONLY IF advisory DB revision proven equivalent.** If DB revision unobservable or changed → `VERIFICATION_REQUIRED`. Since DB revision is not currently part of canonical environment, default is `unavailable`/`VERIFICATION_REQUIRED`. Reuse predicate must check DB identity when available; otherwise fail-closed. This is the canonical example where `RECEIPT_FRESH != EVIDENCE_REUSABLE` holds.

**Summary table:**

| Analyzer | Reusable? | Predicate summary |
|---|---|---|
| RuboCop | REUSABLE UNDER bounded source+config+analyzer_version+ruby equivalence | Fail-closed on external config unobservable |
| RSpec | NOT REUSABLE | Unobservable test dependencies/nondeterminism, DB, ENV, external services |
| Minitest | NOT REUSABLE | Same as RSpec |
| SimpleCov | NOT REUSABLE (independent) | Coupled to test execution; stale coverage risk |
| bundler-audit | REUSABLE ONLY WITH DB equivalence | Fresh receipt insufficient; DB revision must match, otherwise VERIFICATION_REQUIRED |

This supports a mixed outcome but conservative default: **no analyzer is unconditionally reusable on fresh receipt alone.**

## 6. Policy / baseline / waiver interaction

- **Policy changes** (mode, enabled/required, severity thresholds, coverage policy, timeouts, changed/full scope) do NOT invalidate normalized evidence itself, but invalidate old GateResult. Architecture: `reused normalized evidence → current baseline → current waivers → current policy → NEW GateResult`. Old GateResult cannot be reused.
- **Baseline change** — evidence remains valid; gate decision must be reevaluated. New baseline may resolve `introduced` findings. Not `EVIDENCE_REUSABLE` invalidation, but `GATE_REUSABLE` invalidation.
- **Waiver change** — same: evidence valid, waiver evaluation changes outcome. Waiver expiry must be evaluated at current time (UTC) — time matters for waiver validity even if evidence deterministic.
- **Analyzer enabled/required changes** — if previously disabled analyzer now required, previous evidence missing → `VERIFICATION_REQUIRED`. If required coverage now requires evidence not present, incomplete cannot become complete via reuse.

Invariants:
- Reuse cannot bypass baseline/waiver/policy evaluation.
- Required evidence cannot disappear via reuse.
- Old GateResult cannot override current policy.

## 7. Git / source scope

- **Full vs changed verification** — evidence scope matters. Changed-scope evidence is tied to `base`/`merge_base`/`HEAD`. A fresh receipt for `full` does not prove `changed --base X` reusable.
- **Same HEAD but different base/merge_base** → `VERIFICATION_REQUIRED` for changed-scope evidence.
- **Index/worktree/untracked relevant drift** → repository digest changes → `stale` → not reusable.
- **Renames/deletes/staged changes** — captured via `RepositoryState` (`ls-files -s` + porcelain v2 hashes). Must match.
- **Shallow/missing base** → `INCOMPLETE` — cannot reuse as complete.

Predicate: `current_git_scope_identity == verified_git_scope_identity` required for changed-scope evidence.

---

## 8. Environment / dependency interaction

- **Ruby drift (`ruby_version`, `ruby_engine`)** — environment digest covers; drift → stale → not reusable.
- **Analyzer version drift** — relevant enabled versions only; drift of relevant analyzer → stale. Irrelevant tool version drift does not affect.
- **Dependency state (Gemfile.lock, installed gems, Bundler, Rails, native extensions)** — not fully captured in VerificationEnvironment (intentionally minimal for portability). For RuboCop, only plugin versions matter; for RSpec/Minitest, full closure matters — hence not reusable. For bundler-audit, Gemfile.lock + DB revision matter. Adding all installed gems to environment would break portability/clone independence — rejected. Minimum observable state per analyzer (as in §5) is correct.
- **Provenance observation** — via lightweight `--version` probes (bounded, no suite). SimpleCov version probe skipped if no coverage file; bundler-audit version observed.

## 9. Replay analysis

| Replay case | Expected |
|---|---|
| Same repo state restored later (exact revert) | Fresh if digests equal; reusable per-analyzer predicates |
| Old receipt reused after edit + exact revert (content identical, but intermediate mutation) | `fresh` if final state digest matches receipt; evidence reusable if predicates hold (no history sensitivity). Pre/post guard during original verification ensures no mutation during build, but replay after revert is not prevented — correct per identity model. |
| Same commit in different clone (same HEAD/index/worktree/config, different absolute path) | Fresh — path-independent — clone portable; reusable per predicates |
| Previous CI job artifact used by later CI job (equivalent checkout) | Fresh if checkout equivalent; reusable per predicates |
| Branch moves away then returns (same HEAD restored) | Same as revert — fresh if identity equal |
| Same HEAD but different index | Stale (index_digest differs) → VERIFICATION_REQUIRED |
| Same files but different base (changed-scope) | Not reusable for changed-scope evidence |
| Old advisory DB (Gemfile.lock unchanged, DB older) | Not reusable for bundler-audit |
| Old analyzer environment (rubocop upgraded) | Stale → not reusable |

## 10. TOCTOU analysis

Reuse evaluation itself has race surface:

```
observe reusable
  ↓
repository changes
  ↓
construct GateResult (using stale assumption)
```

Must fail-closed. Investigated guard: capture `identity_before = VerificationIdentity.current`, evaluate predicates, then capture `identity_after = VerificationIdentity.current` (re-observe repository + environment). If `before != after` → `VERIFICATION_REQUIRED` / `INCOMPLETE`, never `REUSABLE`. This mirrors `Check.execute_with_state_guard` pre/post pattern.

Also Handoff itself is point-in-time envelope; receiver must independently observe current state — sender timestamps/host/PID not trusted.

Handoff tampering: deterministic `handoff_id = sha256(canonical_json[payload])` excludes volatile fields; any byte change → identity mismatch → `handoff_invalid`/`handoff_tampered`.

## 11. All-or-nothing vs per-analyzer analysis

**Whole-set reuse**: all required evidence reusable → skip all expensive producers, then run policy pipeline.

**Per-analyzer reuse**: subset reusable, e.g., `rubocop: REUSED, bundler_audit: REUSED, rspec: EXECUTED, simplecov: EXECUTED`. Then combine `reused normalized evidence + new normalized evidence → same canonical downstream pipeline`.

Investigation:

- Whole-set is simplest, safest, and already useful if at least one run in CI can skip everything on identical state.
- Per-analyzer is architecturally sound **iff** reused evidence provenance remains bound, completeness preserved, and combination uses same policy engine (no second engine).
- Per-analyzer correctness requires per-analyzer predicates (§5) — which we have, but RSpec/Minitest/SimpleCov are not reusable anyway, limiting benefit.
- Per-analyzer adds complexity: combined evidence ordering, identity, and testing of partial execution paths.
- No evidence that whole-set is insufficient for 1.4's clone-to-clone / CI-job-to-CI-job file-based use case.

**Decision:**

`PER_ANALYZER_REUSE_DEFERRED` — per-analyzer reuse is sound but deferred to 1.5. The sound architecture (§14) supports it without second engine, but 1.4 ships **whole evidence-set reuse** only. This avoids forcing partial reuse to satisfy version title, preserves trust, and delivers useful Handoff/Evidence Reuse if whole-set model proves defensible (it does for RuboCop+lockfile+DB cases; whole-set simply requires all predicates to hold, which for RSpec-including configs means whole-set will usually be `VERIFICATION_REQUIRED` — correct and fail-closed).

Rejected `PER_ANALYZER_REUSE_IMPLEMENTED` because per-analyzer benefit in 1.4 without RSpec reuse is marginal and increases audit surface. Rejected `PER_ANALYZER_REUSE_REJECTED` because model is not incompatible, just deferred.

## 12. Handoff minimum requirements (transport envelope, NOT authorization)

Handoff is deterministic bounded envelope allowing offline receiver to evaluate reuse under current observable state.

Minimum content:

- `schema_version` / `handoff_version` (e.g., `handoff-v1`)
- `handoff_id = sha256(canonical_json[trusted_payload])` (timestamps/PID/host/path excluded; JSON key order insensitive; deterministic)
- `verification_receipt` (the 1.3 Receipt document — already binds VerificationIdentity + gate projection + PR digest + repair binding)
- `evidence_set` — normalized evidence material for reuse candidates: `AnalyzerResult[]` projections (analyzer, execution_status, tool_version, findings[sorted], coverage normalized if applicable) — bounded, no raw stdout, no source dumps, no secrets
- `evidence_provenance` — per-analyzer provenance needed for predicates (tool versions, DB revision if available)
- `source/scope identity` — head, merge_base/base for changed scope, mode, analyzer requirement set at verification time
- Optional relationships: PR Intelligence digest reference (not full doc), RepairPacket linkage (packet_id) — references/digests, not duplicates
- Size bound: `MAX_HANDOFF_BYTES = 256 KiB` (same as RepairPacket), fail-closed on oversized.

Excluded: source files, full logs, env dumps, credentials, AI prompts, arbitrary stdout, huge RSpec JSON. Handoff identity excludes mutable annotations; closed schema for trusted data.

## 13. Security threats

- Tampered Handoff JSON / Receipt inside Handoff → `handoff_invalid` / `receipt_integrity_failed` (ID mismatch)
- Evidence tampering → handoff_id mismatch
- Analyzer version tampering, provenance tampering, GateResult tampering → same
- Source/index/worktree/config/baseline/waivers/base/analyzer/Ruby changes → stale / VERIFICATION_REQUIRED
- Advisory DB drift, lockfile mutation, SimpleCov producer mismatch, required analyzer added/disabled → handled per predicates
- Oversized/malformed/unknown schema/duplicate fields → `handoff_invalid` / bounds check
- Symlink/path escape, executable path injection, shell interpolation → argv-only exec, no command paths from Handoff, no filesystem paths outside repo root, bounded JSON parse
- Replay (edit→revert, cross-clone, old Handoff) → covered in §9
- TOCTOU (§10)
- AI/PR Intelligence/ RepairPacket / MCP cannot authorize reuse — separate authority

All map to fail-closed `VERIFICATION_REQUIRED` / `handoff_invalid` / `unavailable` / `INCOMPLETE`, never ambiguous success.

## 14. Recommended 1.4 architecture

```
Verification (Check.execute_with_state_guard)
  ↓
Verification Receipt (Receipt.build, binds VerificationIdentity + gate projection)
  ↓
Handoff.create(receipt, normalized evidence set, provenance, scope) → handoff_id
  ↓  (file/process/clone/CI artifact transport, untrusted)
Handoff received
  ↓
Receiver independently observes current RepositoryState + VerificationEnvironment → VerificationIdentity.current
  ↓
Freshness evaluation: Receipt.validate_freshness(document, current_identity) → fresh|stale|invalid|unavailable
  ↓ (fresh necessary)
Evidence reuse evaluation: Reuse.evaluate(handoff, current_identity, current_contract{policy, baseline, waivers, scope, required analyzers}) → REUSABLE | VERIFICATION_REQUIRED | INVALID | UNAVAILABLE
  ↓
If REUSABLE (whole-set): reused normalized evidence → current baseline → current waivers → current policy → NEW GateResult (same pipeline, no second engine)
If VERIFICATION_REQUIRED/INVALID/UNAVAILABLE: execute normal verification (Check.execute)
```

One canonical reuse evaluator `Reuse.evaluate` used by CLI, MCP, CI helpers, Repair — no duplicate engines.

Reuse result states: `REUSABLE` vs `VERIFICATION_REQUIRED` plus fail-closed `handoff_invalid`/`unavailable` with machine-readable reasons: `receipt_stale`, `repository_changed`, `environment_changed`, `policy_changed`, `required_analyzer_missing`, `analyzer_version_changed`, `dependency_state_changed`, `advisory_database_changed`, `scope_changed`, `base_changed`, `evidence_incomplete`, `provenance_unobservable`, `handoff_tampered`, `reuse_toctou`.

Determinism: handoff_id, reuse predicate identity, evidence identity, reason ordering deterministic; timestamps/PID/host/path/duration/seed excluded from canonical identity.

TOCTOU guard (§10). Handoff portable, bounded, deterministic content identity (not authorship/signature).

## 15. Explicit rejected alternatives

- **Cryptographic signatures, Sigstore, PKI, signing keys, remote attestation, trusted timestamping** — deferred to 2.x per NON-GOALS.
- **Remote Receipt storage, SaaS, daemon, hosted verification service, GitHub App/webhook, auto-merge** — rejected (local-first, offline-capable).
- **Distributed verification DB / centralized cache / cloud orchestration** — rejected.
- **Reuse old GateResult as authoritative decision** — rejected; reused evidence must produce NEW GateResult via current policy engine.
- **Clock/TTL-based evidence invalidation (`created_at < N`)** — rejected; identity-driven, not clock-driven, except waiver expiry which is policy, not evidence TTL. Advisory DB time relevance is via DB content identity, not generic age.
- **Second reuse policy engine for MCP/CLI divergence** — rejected; one canonical evaluator.
- **Per-analyzer reuse in 1.4** — deferred (see §11), not rejected as unsound.

## Stage 0 Exit Gate

- **RECEIPT_FRESH:** current observable `VerificationIdentity` (repository_digest + environment_digest) equals verified identity bound in Receipt; `Receipt.validate_freshness` returns `fresh` with zero stale/unavailable reasons.
- **EVIDENCE_REUSABLE:** previous normalized evidence is semantically sufficient under currently observed repository state, verification environment, analyzer environment, dependency state (where relevant, e.g., advisory DB), configuration, policy, baseline, waivers, Git/base scope, provenance, and completeness requirements, such that producers need not re-execute; whole-set reusable only if every required analyzer's predicate holds.
- **VERIFICATION_REQUIRED:** evidence is not reusable — previous evidence is stale, missing, incomplete, provenance unobservable, scope mismatched, policy/baseline/waiver boundary changed, or TOCTOU detected — current verification must execute.
- **ANALYZER_EVIDENCE_REUSABLE:** per-analyzer predicate holds for that analyzer's evidence class (deferred for 1.4; defined for future 1.5).

No circular logic: `Evidence is reusable because current receiver independently observed state/environment/provenance and predicates hold` — not `because Handoff says reusable`. Handoff never self-authorizes.
