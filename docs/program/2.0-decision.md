# G5 Distributed Trust — Authorization Decision (mandatory node)

Date: 2026-09-06. Decided on G3/G4 evidence. No 2.0 branch created, no major
bump, no dependencies added.

## Gate evaluation

| Criterion (program §10) | Evidence | Met |
|---|---|---|
| ≥3 independent projects need cross-machine/org evidence transport | All G3 trials single-machine, single-operator; handoffs never left localhost | NO |
| CI and consumer in different trust boundaries | No such topology observed; lab CI fetches the published gem and verifies by SHA (integrity, not identity) | NO |
| Forgery/replay of receipts is a concrete (not imaginary) threat | No forgery attempt, no replay incident, no reporter asked for non-repudiation | NO |
| Identity / trusted builder / organization policy need | Zero spontaneous demand in 5 projects + 20 experiment tasks + lab campaigns | NO |
| Local receipt/handoff without authorship insufficient + observed | Receipts/handoffs sufficed everywhere tested (freshness + reuse + drift) | NO |
| Users accept distributed-trust operational cost | No users engaged at all | NO |

## Decision

```text
DISTRIBUTED_TRUST_NOT_JUSTIFIED
```

Creating an artificial 2.0 to satisfy numbering would be program failure (goal
statement §0). The local-first verifier plus content-bound receipts/handoffs
is the complete product for every observed need.

## What would reopen this

Three independent projects transporting evidence across trust boundaries with
a concrete forgery/replay threat, recorded in a new G3-class campaign. Until
then the 2.0 line stays closed; receipt v1 remains a local integrity record
by design (ADR 0017/0019).
