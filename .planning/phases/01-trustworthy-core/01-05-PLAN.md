  <files>lib/rail_verdict/contracts/gate_result.rb, lib/rail_verdict/verification/policy.rb, test/test_gate_result.rb, test/test_policy.rb</files>

  <action>
`RailVerdict::GateResult` is a frozen envelope (`schema_version "1.0"`, `completion_status`, `gate`, `policy_status`,
finding summaries `{id, fingerprint, severity, state, blocking}` preserving finding order, `analyzer_results`,
`operational_failures`, `decision_reasons`) with constructor invariants mirroring result-v1: complete requires
gate/pass-status triples; incomplete/interrupted require `INCOMPLETE`, `not_evaluated`, and at least one operational
failure; `to_schema_h` emits the exact result-v1 key order. `RailVerdict::Verification::Policy.evaluate(configuration:,
analyzer_results:, findings:)` is the only GateResult factory exported by the verification layer:
(1) any required analyzer with evidence_status `incomplete` → incomplete GateResult carrying each failure as an
operational failure (`code` from the analyzer failure, `analyzer` name, bounded message) with decision reason
`required_evidence_incomplete`;
(2) optional (enabled, not required) analyzer failure still completes the gate but records an operational failure and
decision reason `optional_evidence_unavailable`;
(3) mode `advisory`: blocking false for all; PASS without findings, WARN with findings (reasons
`no_findings_detected` / `advisory_findings_present`);
(4) mode `strict`: blocking true for all; PASS/FAIL (reasons `no_findings_detected` / `blocking_findings_present` with
count);
(5) mode `no_new_debt` evaluates as `strict` and adds decision reason `no_new_debt_evaluated_as_strict` documenting
that Phase 3 owns real no-new-debt semantics.
Finding summaries derive `blocking` from the policy decision; findings keep contract order. Tests: the fail-closed
invariant — for EVERY one of the eight non-succeeded execution statuses, a required analyzer with that status produces
`gate INCOMPLETE`, `policy_status not_evaluated`, and can never produce PASS/WARN/FAIL — plus enabled-but-not-required
failure, advisory WARN/PASS, strict FAIL/PASS, no_new_debt parity with strict plus the extra reason, deterministic
decision reasons, schema validation of complete and incomplete envelopes via json_schemer against result-v1, and
frozen immutability.
  </action>
  <acceptance_criteria>
    - CORE-11: only Policy constructs GateResult; reporter/adapter tests demonstrate no alternate construction path.
    - The suite proves: incomplete required evidence cannot produce PASS (all eight failure statuses).
    - Envelopes validate against `schemas/result-v1.schema.json` in both complete and incomplete shapes.
  </acceptance_criteria>
  <verify>bundle exec ruby test/test_policy.rb && bundle exec ruby test/test_gate_result.rb && git diff --check</verify>
  <done>Gate authority is centralized and fail-closed.</done>
</task>

  <action>
`RailVerdict::Reporters::Console.render(gate_result)` returns a deterministic plain-text projection: header
`RailVerdict <version>`, analyzer section ordered by analyzer id with status/version/finding counts, findings section
in contract order as `<path>:<start>[-<end>] <analyzer>/<rule_id> [<severity>] <message>` with control characters
replaced by `?` (data rendered as data, never interpreted), operational failures, gate line, policy line, and decision
reasons. No timestamps, no randomness, no machine-specific absolute paths, no ANSI escapes, no locale-dependent
formatting.
`RailVerdict::Reporters::JsonReporter.render(gate_result)` returns exactly one JSON document plus one newline:
`JSON.generate(gate_result.to_schema_h) + "\n"` with schema key order; before returning it validates the document
against `schemas/result-v1.schema.json` using json_schemer and raises `RailVerdict::Error` on violation (the CLI then
emits diagnostics on stderr and exits 2, writing nothing to stdout). Tests prove: byte-identical output for identical
inputs; identical canonical content when analyzer_results/findings inputs are permuted (ordering contract); absent
location values sort before present values; console sanitizes ANSI/control-character messages; JSON output is a single
document with a trailing newline and no extra stdout material; diagnostics never appear on stdout.
  </action>
  <acceptance_criteria>
    - CORE-12: deterministic console; exactly one result-v1 document plus newline in JSON mode.
    - Reporters never mutate the GateResult and never compute gate state.
    - Ordering tests pin the documented finding/analyzer ordering including absent-value rules.
  </acceptance_criteria>
