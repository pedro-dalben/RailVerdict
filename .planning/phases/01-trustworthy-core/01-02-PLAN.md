<objective>
Implement CORE-03 strict configuration loading and CORE-04 immutable RunContext with deterministic execution inputs.
No global mutable state; configuration errors fail explicitly with path-specific messages and never fall back silently.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Strict configuration loader</name>
  <files>lib/rail_verdict/configuration.rb, test/test_configuration.rb, test/fixtures/configurations/</files>
  <read_first>
    @schemas/configuration-v1.schema.json
    @docs/contracts.md
    @.planning/phases/01-trustworthy-core/01-CONTEXT.md
  </read_first>
  <action>
Implement `RailVerdict::Configuration.load(path)`:
(1) missing file raises `ConfigurationError` citing the resolved source path;
(2) bytes must be valid UTF-8 and BOM-free, else an encoding error citing the path;
(3) parse with `Psych.parse` node walking: reject aliases, anchors, and any explicit tag; detect duplicate mapping keys
with the nested property path; then materialize plain data (maps, arrays, nil, booleans, integers, floats, strings)
using YAML core scalar interpretation for plain scalars;
(4) validate the data value against `schemas/configuration-v1.schema.json` with `json_schemer`, translating every error
to `$.property.path` style messages; reject unknown keys through the closed schema;
(5) expose frozen effective values: `version`, `mode`, `analyzers` selections, `source_path`, and `digest`
(SHA-256 hex of the raw file bytes) as the configuration identity.
Errors never echo secret or scalar values; only paths and constraint names are reported. Add fixture files under
`test/fixtures/configurations/`: valid, duplicate_key, alias_anchor, object_tag, unknown_key, disabled_required,
wrong_version, missing_mode, invalid_utf8 (bytes), and bom. Tests must cover every fixture plus the effective-value and
digest behavior, and assert `YAML.safe_load` equivalence is unnecessary because the node walker is the loader.
  </action>
  <acceptance_criteria>
    - Every rejection names the source file and the property path (`$.analyzers.rubocop.enabled` style).
    - No code path constructs objects from YAML tags or permits symbol/class deserialization.
    - The valid fixture round-trips to the documented effective values and a stable digest.
  </acceptance_criteria>
  <verify>bundle exec ruby test/test_configuration.rb && git diff --check</verify>
  <done>Configuration loading is strict, path-specific, and fail-closed.</done>
</task>

<task type="auto">

  <action>
Implement frozen `RailVerdict::RunContext.build(repository_root:, configuration:, analyzer_versions:, revision_resolver:)`
recording: repository root (realpath, verified directory), revision (`revision_resolver.call` returning the git HEAD sha
or nil when absent), runtime `ruby_version` (`RUBY_VERSION`), `target_ruby_version` and `rails_version` parsed read-only
from `Gemfile.lock` when present (RUBY VERSION section; `rails (x.y.z)` spec entries; nil otherwise), `analyzers`
selection map from configuration, `analyzer_versions` hash (nil values allowed when unavailable),
`configuration_mode`, `configuration_digest`, and frozen `deterministic_inputs`
(`{"locale" => "C.UTF-8", "timezone" => "UTC", "ordering" => "canonical-v1"}`). The object must be deeply frozen: no
mutators, no accessors returning unfrozen internals (return duplicated frozen copies). Tests prove immutability
(`frozen?` on context and nested values), revision resolution against a temporary git repository and nil for a
non-repository directory, Gemfile.lock parsing for Rails 8.x and absence cases, and deterministic digest capture.
Git resolution is injected as a callable so tests never depend on the repository's real history; the production
resolver is wired in plan 01-06 through the safe process runner.
  </action>
  <acceptance_criteria>
    - CORE-04: all required deterministic inputs are present, immutable, and free of global mutable state.
    - `RunContext` never mutates after construction and exposes no writer methods.
    - Revision/Rails/Ruby detection degrade to explicit nil values rather than guesses.
  </acceptance_criteria>
  <verify>bundle exec ruby test/test_run_context.rb && git diff --check</verify>
  <done>RunContext captures deterministic execution inputs immutably.</done>
