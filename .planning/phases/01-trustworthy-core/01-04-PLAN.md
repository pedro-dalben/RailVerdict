`RailVerdict::Finding` is a frozen value object enforcing at construction: `schema_version "1.0"`, enum membership for
origin/severity/confidence/state (Phase 1 emits only `deterministic` and `observed`), full `sha256:` 64-hex
fingerprint, repository-relative location path rules (no leading `/`, no backslashes, no `.`/`..` segments, no empty
segments, no control characters), `end_line >= start_line` when both present, message length 1..4096, and non-empty
`evidence_ref`. Provide `Finding.fingerprint_for(analyzer:, rule_id:, path:, message:)` computing SHA-256 over the
documented draft payload with sorted keys, and deterministic `id` `rv:<first 20 hex>`; constructor deduplication is the
caller's job but identical fingerprints must produce identical ids. Provide `sort_key` implementing the contract
ordering (path, start line absent-before-present, end line absent-before-present, analyzer, rule id, fingerprint, id)
and `to_schema_h` emitting exactly the finding-v1 key order. Tests assert every invariant rejects bad input, the
fingerprint is stable across key orderings of the input hash and independent of line numbers, and the schema document
validates against `schemas/finding-v1.schema.json` using `json_schemer` (bundled with the gem) — including rejection
of an injected `blocking` field.
`RailVerdict::AnalyzerResult` is a frozen value object over `analyzer`, `invocation` (executable + argv array, argv
verbatim), `tool_version` (nil allowed), `execution_status` enum, `evidence_status` (`complete` iff status is
`succeeded`), `finding_ids`, and `failure` (`{code:, message:}` required exactly when not succeeded). Constructor
enforces these invariants; `to_schema_h` emits exactly the result-v1 `analyzer_result` shape. Tests cover every status,
the succeeded⇔complete⇔no-failure invariant, schema-shape output, and frozen immutability.
  </action>

  <name>Task 2: RuboCop adapter with fail-closed failure corpus</name>

  <action>
Implement `RailVerdict::Analyzers::RuboCop` with an injectable `command_resolver` (default: when the repository root
contains a `Gemfile`, `bundle exec rubocop`; otherwise bare `rubocop`; never install anything). `probe(root, runner:)`
runs `... --version` through the safe runner and returns availability + parsed version; `run(root, runner:, timeout:)`
runs `... --format json` and returns `[AnalyzerResult, [Finding]]`. Interpretations: spawn failure → `unavailable`;
nonzero version probe → `unavailable`; unparseable or out-of-range version (outside `>= 1.72, < 2`) → `unsupported`;
timeout → `timed_out`; child killed by signal → `signaled`; truncated stream → `truncated`; exit >= 2 → `failed`;
exit 0/1 with unparseable JSON → `parse_failed`; exit 0/1 with JSON whose shape violates expectations (missing `files`,
non-array, invalid offense structure, unknown severity, cop without department, absolute/escaping path, end before
start line, message over 4096 or invalid UTF-8) → `malformed`. Successful runs normalize offenses: severity mapping
info→info, refactor→low, convention→low, warning→medium, error→high, fatal→critical; category = lowercase cop
department; origin `deterministic`; confidence `high`; state `observed`; location from `start_line`/`last_line`;
relative path normalized (strip leading `./`); draft fingerprint; `evidence_ref` `native:rubocop:<fp12>`; findings
deduplicated by fingerprint and sorted by `sort_key`; finding ids recorded in order. Invocation provenance records the
executable and verbatim argv. Add stub fixtures: `fake_rubocop_clean`, `fake_rubocop_offenses` (multiple files,
shuffled offense order, including a duplicate offense), `fake_rubocop_version` variants (supported `1.88.0`,
unsupported `0.93.0`, garbage), `fake_rubocop_bad_json`, `fake_rubocop_shape_violations` (unknown severity; absolute
path; missing files key), `fake_rubocop_exit2`, `fake_rubocop_slow`, `fake_rubocop_flood` — each a tiny Ruby script
emitting deterministic English-only output, selected via resolver injection `{executable: RbConfig.ruby, args_prefix:
[stub_path]}`. Tests assert every state, normalization invariants, dedup+ordering determinism (shuffled input yields
identical output), invocation provenance equality, and that no failure path yields an empty successful result.
  </action>
