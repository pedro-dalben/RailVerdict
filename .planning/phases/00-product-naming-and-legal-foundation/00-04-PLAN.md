<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted YAML/JSON -> parsed configuration/Finding | Repository-owned documents cross a strict validation boundary. |
| Schema reference -> resolver | References must not trigger network access or fetch mutable remote content. |
| Analyzer Finding -> policy decision | Evidence input must not inject gate authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-10 | Tampering | nested schema objects | mitigate | Close every object and test unknown root/nested mutations against Draft 2020-12. |
| T-00-11 | Information Disclosure | YAML loading | mitigate | Validate a Psych safe-loaded data value with no classes, symbols, aliases, ERB, or object tags. |
| T-00-12 | Spoofing | schema references | mitigate | Permit only local fragment `$ref` values and validate with no network resolution. |
| T-00-13 | Elevation of Privilege | Finding gate fields | mitigate | Reject analyzer-supplied gate authority; policy decisions remain a separate future contract. |
| T-00-SC | Tampering | schema-validation dependency | accept | Use the environment-provided validator only for Phase 0 checks; add no project or runtime dependency. |
</threat_model>
