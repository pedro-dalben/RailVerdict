  <action>
Create schemas Draft 2020-12, `additionalProperties: false`:

- `schemas/waiver-v1.schema.json` `$id: https://railverdict.dev/schemas/waiver/v1.schema.json`:
  required `fingerprint (pattern ^sha256:[0-9a-f]{64}$)`, `reason (string 1..1024)`, `owner (string 1..256)`, `created_at (string date-time with Z)`, `expires_at (string date-time with Z)`, optional `issue_ref (string 1..512)`. Runtime check: `expires_at > created_at`, both must end with `Z` (UTC), no timezone offset. Reject `*`, `Style/*`, empty, glob patterns as malformed (they won't match pattern anyway; also reject array/wildcard fingerprints at store level).

- `schemas/waivers-v1.schema.json` `$id: https://railverdict.dev/schemas/waivers/v1.schema.json`:
  `{schema_version: const "1.0", waivers: array of waiver-v1 entries, entries sorted by fingerprint in runtime validation}`.

Implement `lib/rail_verdict/waiver.rb`:

- `Waiver::IncompatibleError < RailVerdict::Error`.
- `Waiver.new(hash)` validates via schema + `expires_at > created_at` + UTC check; frozen.
- `Waiver.active?(waiver, clock: Time.now.utc)` → `created_at <= clock && clock < expires_at` with UTC times (parse via `Time.iso8601`, ensure UTC).
- `Waiver.valid_fingerprint?(fp)` checks pattern.

Implement `lib/rail_verdict/waiver_store.rb`:

- `WaiverStore.default_path(root)` → `.railverdict-waivers.json`.
- `WaiverStore.resolve_path(root:, configuration:, waiver_override:)` precedence like baseline.
- `WaiverStore.read(path)` → binread, parse, validate against `waivers-v1` schema + duplicate fingerprint check + per-waiver UTC check; on malformed/unknown version/corrupted/over-broad → raise `Waiver::IncompatibleError` with migration hint `waiver file incompatible: …; fix the file or remove the waiver`.
- `WaiverStore.read_optional(path)` → nil if missing (no waiver file is not an error).
- Never support wildcard waivers — store rejects any entry whose fingerprint is not exact `sha256:…`.

Extend `SchemaValidator` with `validate_waiver` / `validate_waivers`.

Extend `schemas/configuration-v1.2.schema.json` to allow optional `waivers: {type: object, properties: {path: {type: string, minLength: 1, maxLength: 1024}}, additionalProperties: false}` alongside `baseline`. Update `Configuration` to expose `waivers_path` accessor. Keep additive.

Require from `lib/rail_verdict.rb`.
  </action>

    - UTC expiry is deterministic with injected clock; no timezone-dependent behavior.

Wire waivers into the read-only check path:

- `Check.execute` gains optional `clock: Time.now.utc` injection (default real clock) for tests; resolve waiver path like baseline, call `WaiverStore.read_optional`. On `Waiver::IncompatibleError`, surface as operational failure `code: waiver_incompatible` with migration message and include `waivers_compatible: false` in GateResult baseline/waivers metadata — still produce a GateResult (operational_failures non-empty may make INCOMPLETE if policy decides? Keep consistent: waiver incompatibility is visible but does not alone make required evidence incomplete; yet should be fail-closed enough to be noticed — add `decision_reasons` entry and do not suppress findings). Ensure check remains read-only (no waiver file mutation; test mtime unchanged).

- `Comparison.classify(findings:, baseline:, waivers: [], clock:)` — partition findings first via baseline, then overlay active waivers: any finding whose fingerprint matches an active waiver (active per clock) is restated with `state: "waived"` (visible, not hidden). Expired waivers are ignored for suppression — finding retains its baseline-derived state (e.g., `introduced`). Orphaned waivers (fingerprint not in any current finding nor baseline entry) are collected as `orphaned_waivers` array (frozen, sorted) and exposed via `Comparison::Result`.

- `Policy.evaluate` — when `comparison` contains waived findings, those findings are non-blocking while waived (unless mode is strict? For waived, default non-blocking in all modes while active; once expired they flip back to blocking per mode). Expired waivers therefore block again in `no_new_debt`/`strict`. Add `decision_reasons` like `waived_findings_suppressed` and `expired_waivers_visible`.

- CLI `check` already parses `--baseline`; add `--waiver PATH` optionally. Baseline/waiver discovery is explicit path or config or default file — no glob.

Tests:

- `test/test_waivers.rb`: active exact waiver → finding becomes waived, visible, non-blocking; wildcard pattern rejected as malformed; malformed file raises with hint.
- `test/test_waiver_expiry.rb`: with injected clock before `expires_at` → waived non-blocking; after `expires_at` (UTC) → waiver no longer suppresses, finding blocks again (no_new_debt FAIL); clock injection proves no locale/tz dependence (use Time.utc).
- Orphaned waiver: waffle fingerprint not in findings/baseline → `orphaned_waivers` observable and not discarded; expired waiver remains visible in store result.
- Malformed/incompatible waiver file surfaces as operational failure and does not silently suppress.
- `Check` with waiver file does not mutate waiver/baseline files (mtime).

Keep `git diff --check` clean.
