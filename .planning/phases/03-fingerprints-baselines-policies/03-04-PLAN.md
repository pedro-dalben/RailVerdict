Extend `Policy.evaluate(configuration:, analyzer_results:, findings:, comparison: nil)`:

- Keep early fail-closed: if `required_incomplete` non-empty → `INCOMPLETE`/`not_evaluated` immediately, ignoring baseline/comparison (hard invariant). Remove the Phase 01 reason `no_new_debt_evaluated_as_strict`.

- Partition findings via comparison when present:
  `existing_ids = Set[comparison.existing.map(&:fingerprint)]` etc. Map each finding to `{finding, state}` where state comes from Comparison (existing/introduced/changed/moved). Waived handling comes next plan — treat all as their comparison state for now.

- Implement modes:
  * `advisory`: gate `PASS` if findings empty else `WARN`; all findings `blocking: false`; `policy_status` `pass`/`warn` accordingly; `decision_reasons` include `advisory_findings_present` when findings present, `advisory_non_blocking` hint.
  * `no_new_debt`: `existing` findings are non-blocking (`blocking: false`); `introduced|changed|moved` are blocking (`blocking: true`) — default any severity blocks. If `blocking` set is empty → `PASS`; else `FAIL`. `policy_status` `pass`/`fail`. `decision_reasons` include `existing_debt_retained` (count), and `introduced_findings_blocking` or `regression_findings_blocking` with count when failing. No new `rubocop:`-style analyzer-specific keys.
  * `strict`: all current findings `blocking: true` irrespective of baseline → `PASS` if empty else `FAIL`; `decision_reasons` mirror current `blocking_findings_present`.

- Update `summaries(findings, blocking:)` is no longer uniform — build summaries per-finding with per-state blocking derived above; keep method signature compatible or add `summaries_with_states`.

- Policy remains analyzer-independent: operate only on `severity/category/state/evidence_summary completeness` (zero-tests, stale coverage already handled). No `rule_id`-specific branching.

- Ensure `GateResult` still validates: `complete` with `gate∈{PASS,WARN,FAIL}` and `policy_status∈{pass,warn,fail}`; findings summaries sorted by `sort_key`.

Tests in `test/test_policy_modes.rb`:

- Matrix with fixtures built via `Finding.fingerprint_for` + `Comparison` + `Baseline` in-memory:
  - 0 findings → PASS in all modes.
  - N existing + 0 introduced → advisory WARN, no_new_debt PASS (existing non-blocking), strict FAIL (any finding blocks).
  - N existing + 1 introduced → advisory WARN non-blocking, no_new_debt FAIL, strict FAIL.
  - incomplete evidence (e.g., RuboCop unavailable) with baseline of 100 entries → INCOMPLETE regardless of baseline (early return).
  - Determinism: same inputs under shuffled analyzer order produce same JSON.

Keep assertions English-only, no analyzer-specific policy like `rubocop: {fail_on: ...}`.
