Create `lib/rail_verdict/comparison.rb`:

- `Comparison::Result = Struct.new(:existing, :introduced, :resolved, :changed, :moved, :counts, :baseline, keyword_init: true)` plus `findings_by_state` helper.
- `Comparison.classify(findings:, baseline:)` where `baseline` is `Baseline` or nil (no baseline → all findings `introduced`, `resolved = []`). When baseline present, build `baseline_by_fp = Hash[entries.map{fp => entry}]` and `current_by_fp = Hash[findings.map{fp => finding}]`.
  - `existing = intersection` → findings restated with `state: "existing"` (new Finding objects with same fingerprint but `state` reassigned).
  - `introduced` = current-only not matched below → `state: "introduced"`.
  - `resolved` = baseline-only → synthetic hashes `{fingerprint, analyzer, rule_id, path, state: "resolved"}` (not Finding instances if state resolved requires no location line — keep minimal but validate against schema state enum).
  - Heuristic for `moved`/`changed` only when unambiguous: if an introduced fingerprint's `analyzer+rule_id+message` matches exactly one resolved entry's stored analyzer/rule/path/message (reconstruct message from? baseline stores minimal fields — include `message` in baseline entry for this; extend baseline entry to hold `message` bounded 1..4096). Then:
    * if path differs but message and rule identical → `moved`.
    * if path same but message differs with same analyzer/rule → `changed`.
    Otherwise keep `introduced`/`resolved`. If multiple resolved candidates share same analyzer+rule+message → ambiguous → keep deterministic `introduced`+`resolved` (no guessing).
- Deterministic ordering: all output arrays sorted by `finding.sort_key` or fingerprint string; Hash lookups, no FS enumeration.
- Require `fingerprint_version` compatibility check already done by `Baseline.read`; if baseline nil, Comparison still works.
- Restate findings via `Finding.new` with same fields but new `state`; ensure `finding.to_schema_h` still validates.

Expose `Comparison::Result#to_h` for reporters/policy and `Comparison::Result#classified_findings` (merged existing+introduced+changed+moved sorted).

Tests in `test/test_comparison.rb`:

- All-intersection → all existing.
- 2 remain + 1 resolved + 1 introduced classification.
- Path move: single resolved matching message+rule but different path → moved.
- Message change: same path+rule but different message → changed.
- Ambiguous multi-match → stays introduced+resolved.
- Duplicate fingerprint (two findings with identical 4-tuple deduped upstream) → treated as one existing; copied code with different paths → distinct fingerprints → one existing one introduced.
- No baseline → all introduced.
- Determinism: shuffled input order produces same classified output.
- Large baseline (e.g., 2k entries) lookup is Hash-based — test that classify completes < 100ms or at least prove no O(n²) scan by counting comparisons if feasible; otherwise assert correct counts for 500 entries.

Keep baseline entries extended to include `message` (needed for heuristics) and validate length. If prior baseline schema already frozen without `message`, add it now as required field 1..4096 with migration note; update schema accordingly before this plan merges.

Require from `lib/rail_verdict.rb`.
