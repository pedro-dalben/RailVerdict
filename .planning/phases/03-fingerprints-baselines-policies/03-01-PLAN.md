Create `lib/rail_verdict/fingerprint.rb` as the single fingerprint authority:

- Constants: `VERSION = 1`, `ALGORITHM = "sha256"`, `PAYLOAD_SCHEMA = "https://railverdict.dev/fingerprint-payload/v1"`, `FINGERPRINT_PATTERN = /\Asha256:[0-9a-f]{64}\z/` (same as Finding).
- `Fingerprint.canonical_payload(analyzer:, rule_id:, path:, message:)` normalizes inputs:
  path: strip leading "./", reject absolute/empty/traversal, validate against Finding::LOCATION_PATH_PATTERN semantics, NFC-normalize via unicode_normalize if available, freeze;
  message: use analyzer shared `bounded_message` semantics (trim, collapse internal whitespace? — keep minimal: strip, UTF-8 valid, 1..4096 bytes, invalid bytes replaced with "?"), NFC.
- `Fingerprint.hexdigest(analyzer:, rule_id:, path:, message:)` builds payload hash `{payload_schema, fingerprint_version, algorithm, analyzer, rule_id, path, message}` with sorted keys, `JSON.generate(canonical)`, `Digest::SHA256.hexdigest`, prefix `sha256:`.
  Also expose `Fingerprint.canonical_json(...)` for testability.
- `Fingerprint.compatible?(fingerprint)` and `Fingerprint.version_for(fingerprint)` helpers are optional; at minimum expose `VERSION` and `PAYLOAD_SCHEMA` for baseline to record.
- Define `Fingerprint::IncompatibleError < RailVerdict::Error` for callers that encounter unknown version/algorithm.

Evolve `Finding.fingerprint_for(analyzer:, rule_id:, path:, message:)` to delegate to `Fingerprint.hexdigest` so existing call sites (every adapter) keep working without change. Keep `Finding.id_for` and `Finding::FINGERPRINT_PATTERN` unchanged. Ensure `Finding::FINGERPRINT_PAYLOAD_SCHEMA` is updated or aliased to `Fingerprint::PAYLOAD_SCHEMA` and documented.

Update `lib/rail_verdict/errors.rb` if a new error class is needed; otherwise keep errors there.

Require the new file from `lib/rail_verdict.rb` before `contracts/finding`.

Write `test/test_fingerprint.rb` (Minitest::Test, frozen_string_literal) with table-driven regression vectors, each asserting `Fingerprint.hexdigest` / `Finding.fingerprint_for` behavior:

- unrelated lines inserted above a finding (same fingerprint when start_line changes)
- finding moves to another line (same fingerprint)
- file rename (different path → different fingerprint; document limitation)
- logical code move (same analyzer/rule/message but different path → different fingerprint; no file+line trick)
- same rule appearing multiple times with distinct messages/paths → distinct fingerprints
- duplicate findings (identical 4-tuple) → identical fingerprint (SHA-256 collision negligible; document as intentional dedup signal)
- copied code (same fingerprint at two locations if message/path identical; if path differs, fingerprint differs — document honestly)
- normalized path changes: "./app/models/user.rb" vs "app/models/user.rb" → same fingerprint after normalization; "app//models/user.rb" rejected
- message variation: whitespace-trimmed messages produce same fingerprint when normalized; materially different message → different fingerprint
- actual semantic change: rule_id change → different fingerprint
- fingerprint-version migration: v0.1 payload vs v1 payload produce different digests; baseline reader must not reinterpret v0.1 as v1 (test that old payload hash != new)
- collision handling assumption documented: SHA-256 collision is not handled; identical payloads intentionally share digest.
- determinism: JSON key order invariant (sorted), locale/timezone do not change digest (control env).

Update `test/test_finding.rb` to assert new payload_schema version if it checks old constant.

Update `docs/contracts.md` fingerprint section: replace draft payload description with v1 payload fields, state that line numbers/timestamps/absolute paths are excluded, document known limitations (rename, copy, no AST), and cross-link ADR 0005.

Update `docs/adr/0005-fingerprint-baseline.md`: set `Implementation status: Implemented in Phase 03 plan 03-01` and note payload v1 details.

Keep tests deterministic, English-only, no network, no private fixtures.
